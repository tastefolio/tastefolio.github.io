# Tastefolio

**Distinct, production-ready design-language skills for AI coding agents.**
Each skill is a standalone `SKILL.md` folder that teaches an agent one complete visual language — tokens, layout logic,
typography, components, interaction and a pre-ship checklist — for both **public websites** and **dashboards / user
panels**, in **English (LTR)** and **Persian (RTL)**.

**Gallery:** https://tastefolio.github.io · **فارسی:** https://tastefolio.github.io/fa/ · **Guide:** https://tastefolio.github.io/guide/ · [README به فارسی](README.fa.md)

- **29 styles** that differ in layout logic, density, typography, navigation and interaction — not just in color.
- **58 working demos** (a site and a dashboard per style) with real menus, tabs, filters, forms, dialogs and charts, all switchable between English and Persian, light and dark, and any brand color.
- **Real screenshots** of every demo in the gallery, captured automatically on every deploy.
- **Framework-free**: plain HTML/CSS plus a tiny shared runtime, with Tailwind v3/v4 and shadcn/ui mappings for each style.

## Install

Pick one method. A skill's name is its folder name (e.g. `raster`). Use **one style per project**.

**Claude Code plugin marketplace**

```
/plugin marketplace add tastefolio/tastefolio.github.io
/plugin install raster@tastefolio
```

`/plugin install tastefolio-all@tastefolio` installs every style at once.

**Skills CLI** (agents that support the open `SKILL.md` format)

```bash
npx skills add tastefolio/tastefolio.github.io --skill raster
```

**Manual**

Copy `skills/<name>/` to `.claude/skills/<name>/` in your repo (shared with the team) or to `~/.claude/skills/<name>/`
(all your projects). Zips are published at `https://tastefolio.github.io/downloads/<name>.zip`, and everything at
[`tastefolio-skills.zip`](https://tastefolio.github.io/downloads/tastefolio-skills.zip). For tools without skill
support, add the skill's `SKILL.md` to the project rules or point the agent at it.

## Use it

Name the style in your request, or record it in `CLAUDE.md` so every session follows it:

```md
## Design
Use the Tastefolio "raster" skill for every UI change.
Brand color: #e4002b
Languages: en (LTR, default) and fa (RTL)
Stack: Next.js + Tailwind v4 + shadcn/ui
```

Example requests:

```
Using the raster style, build a landing page for an architecture festival:
hero, program with filters, speakers, tickets and a newsletter form.

Now build the organizer dashboard for the same festival:
KPIs, ticket sales chart, attendee table with search, settings.
```

The agent reads the skill's identity rules, tokens and patterns, uses the kit (or maps it onto your stack with
`references/adapters.md`) and checks its work against the pre-ship checklist.

## Inside a skill

```
skills/raster/
├── SKILL.md                  # identity rules, tokens, patterns for sites and dashboards, RTL, a11y, checklist
├── meta.json                 # gallery metadata (en + fa)
├── assets/
│   ├── tokens.css            # required: semantic tokens, dark theme, Persian overrides
│   ├── kit.css               # reference components for this style
│   └── kit.js                # shared runtime (copied from shared/kit.js)
├── references/adapters.md    # Tailwind v4 @theme, Tailwind v3 config, shadcn/ui variable mapping
└── examples/
    ├── site.html             # public website demo
    └── dashboard.html        # dashboard / user panel demo
```

A style that needs behaviour of its own ships it as an extra asset next to the kit — Dot's `assets/matrix.js` draws
its LED matrix and glyph editor.

Every `tokens.css` uses the same semantic names (`--canvas`, `--surface`, `--ink`, `--line`, `--brand`, `--success`…,
`--chart-*`, `--font-*`, `--fs-*`, `--space-*`, `--radius-*`), so the kits, adapters and charts work identically across
styles while each style sets its own values and rules.

## Customize without losing the style

- **Brand color:** change `--brand` only; `--brand-soft` / `--brand-strong` derive from it. Each `SKILL.md` states the allowed range.
- **Dark mode:** `<html data-theme="dark">` (dark-first styles also ship a light theme).
- **Persian & RTL:** `<html lang="fa" dir="rtl">`. Kits use CSS logical properties and mirror automatically. Persian is
  set in **Vazirmatn** in every style; numbers use Persian digits and dates the Solar Hijri calendar via `Intl`.
- **Frameworks:** `references/adapters.md` maps the tokens to Tailwind v4 (`@theme inline`), Tailwind v3 and shadcn/ui.

## The shared runtime

`shared/kit.js` (≈50 KB, ≈16 KB gzipped, no dependencies) powers every demo through declarative attributes: language
and theme switching, tabs, pressed groups, switches, dialogs and drawers, filters and live search, table sorting,
form validation, multi-step wizards, steppers, conditional fields, carousels, toasts, command palettes and hotkeys,
copy buttons, `Intl` number/date formatting (Persian digits, Jalali dates, durations) and SVG charts — line, area, bar,
stacked, sparkline, donut and candlestick. The header comment of the file documents every hook.

## Develop

Requires Node 20+.

```bash
npm ci
npx playwright install chromium
npm run dev
```

`npm run dev` serves the repo at http://localhost:4173 — open `/skills/<name>/examples/site.html`.

| Script | What it does |
|---|---|
| `npm run sync` | copies `shared/kit.js` into every skill, regenerates `references/adapters.md` and `.claude-plugin/marketplace.json` |
| `npm run check` | validates every skill: required files, frontmatter, `meta.json`, demo wiring, marketplace |
| `npm run shots` | captures desktop and mobile screenshots of every demo in both languages (Playwright) |
| `npm run build` | builds the gallery into `dist/` (English + Persian pages, zips, `catalog.json`, `llms.txt`, sitemap); with `GITHUB_TOKEN` set it also reads each skill's 👍 votes for the Top rated order |
| `npm run linkcheck` | verifies every internal link and asset in `dist/` |
| `npm run test:gallery` | drives the built gallery in Chromium: filters, search and counts, the screenshot viewer, install tabs, the phone menu, and no sideways scrolling at 320px and 390px |
| `npm run ci` | all of the above, in order — the same pipeline GitHub Actions runs |
| `npm run serve` | serves `dist/` at http://localhost:4174 |

Every push to `main` runs that pipeline and deploys the gallery to GitHub Pages
(`.github/workflows/pages.yml`). It also runs every hour to pick up new votes: every card and skill page has a
👍 vote and comments box (GitHub Discussions through giscus), and the gallery's Top rated order counts the 👍.

**Adding a style:** create `skills/<name>/` with the files above (copy an existing skill as a starting point), give it
its own identity rules, build both demos with the skill itself, then run `npm run ci` and look at the screenshots.
